01 / CI/CD and testingCI/CD Test Management PlatformA multi-service platform for running, monitoring, and analyzing automated tests across different hardware and software configurations. expand_more

Architecture

I designed the system as a set of cooperating services: a backend processing Jenkins webhooks, a business-logic API, a React interface, and a relational PostgreSQL database modeled and migrated with Prisma.

CI integration

The platform triggers parameterized Jenkins jobs for a selected project, variant, hardware target, and system image. Results are collected automatically and matched to internal test runs using queue identifiers and build numbers.

Data and analytics

Parsers normalize different result formats into a common data model. Dashboards present pass rates, failure history, first occurrences, and regressions recurring across consecutive runs.

Operations and security

A WebSocket connection updates test states. JWT and user roles protect access, while the Docker Compose environment uses Nginx, service health checks, database backups, and a rollback procedure for failed deployments.

02 / Embedded and hardwareEmbedded Linux Test FarmInfrastructure for repeatable test execution on physical embedded boards, multiple SoC platforms, and system images. expand_more

Environment

The farm consists of physical Linux development boards, multiple hardware and SoC variants, and managed firmware and system images. Devices are shared across multiple test suites.

Automation

Jenkins selects a device that meets test requirements, prepares the environment, deploys the correct image, runs tests, and collects logs and artifacts. Python and Bash scripts handle the orchestration.

Infrastructure resilience

Health checks detect unavailable nodes, and recovery procedures restore devices that become unresponsive. Every run includes controlled environment setup and cleanup.

Diagnostics

I remotely analyze processes, services, networking, and application and system logs. This makes it possible to distinguish test-infrastructure failures from application, operating-system, and hardware-integration issues.

03 / Computer vision & edge AIAI Posture Analysis SystemA custom RGB-D system combining AI models with geometric analysis to detect and classify potential postural abnormalities. expand_more

Goal

I am building a device that captures the body using RGB and stereo vision, locates key anatomical landmarks, performs quantitative posture analysis, and assesses whether the resulting parameters indicate a postural abnormality.

Analysis method

I am developing the system along two complementary paths. The algorithmic layer compares angles, distances, height differences, and asymmetries across front, rear, and side views. In parallel, I am developing an AI model intended to classify abnormalities from patterns learned from data rather than relying solely on manually defined rules.

RGB-D and edge AI

The OAK-D camera calculates stereo depth and provides synchronized RGB-D data, while a Raspberry Pi 5 runs the pipeline and processes the results. My work covers depth-map alignment and filtering, point clouds, 3D coordinates, and inference optimization within the OpenVINO ecosystem.

Technical challenge

Standard pose-estimation models do not provide sufficiently precise and repeatable landmarks for the shoulder blades, pelvis, or torso axis. I am therefore developing a method for locating custom, symmetrical anthropometric points needed to calculate posture parameters reliably.

My scope

I independently lead the research and software work: designing the hardware/software architecture, building DepthAI pipelines, integrating computer-vision models, developing measurement algorithms, and evaluating successive methods on real RGB-D data.

04 / Geospatial systemSentinelHub · Flood-aware routingWorking application: load an example, calculate a detour around a flooded road, and save the result. User GeoJSON, private workspaces and SQLite history. expand_more
Open application — no files or account neededopen_in_newView source on GitHubopen_in_new

Try it in two steps

Open the application, click “WCZYTAJ PRZYKŁAD” (load example), then “Oblicz i zapisz analizę” (calculate and save). No account or files are needed. Labelled synthetic inputs run through the real backend: see the detour, compare distances, and retrieve the saved result from history. Sample GeoJSON downloads and user uploads are also available.

Graph and geometry

FastAPI validates road and flood GeoJSON. NetworkX builds a directed graph and Shapely identifies intersecting segments. Analysis compares the shortest route before and after flooded roads are excluded, and explicitly reports when no route remains.

Persistence and privacy

SQLite persists versioned inputs and results. A private workspace key protects reads and writes; revision checks prevent conflicting updates. An SVG interface displays roads, flood zones and routes, with result export.

Deployment and verification

The application runs on Raspberry Pi 5 / Linux ARM64 in an isolated Docker Compose stack with Nginx and a persistent volume. All 101 tests passed on ARM64. Public HTTPS browser checks cover the user workflow and readback after container recreation; SQLite backup and restore were verified on the server.

Integration status and limitations

Real OpenStreetMap ingestion through Overpass was verified on the server. Sentinel WMS ingestion remains unavailable until the expired account is renewed. The public example uses synthetic data, and the application also accepts user data. Results are graph analysis, not evacuation guidance or proof of road safety. The demo address is temporary and changes when the tunnel restarts.

05 / Agent systemDual-Agent Support SystemA Java application with an intent router and separate agents for technical and billing support. expand_more

Concept

One multi-turn conversation handles two different request types. A router identifies message intent and passes the shared context to either the technical or billing agent.

Technical agent

Answers are limited to local documentation files. When the material does not contain the required information, the agent asks for clarification instead of generating an unsupported answer.

Billing agent

It handles plan-pricing questions and refund timelines. It can also open a refund case after collecting an email address and the reason for the request.

Implementation and my scope

I designed the router, both agents, context handling, and response rules. The project runs on Java 17, uses the OpenAI API, builds with Maven Wrapper, and includes a Docker image.
