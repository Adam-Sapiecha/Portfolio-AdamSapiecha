Context and purpose

Work on SoC platforms involves operations across multiple computers and physical devices. Board preparation, firmware flashing, job execution and result collection need to work together with applications and CI/CD infrastructure.

The tools we develop reduce manual workflow handling. The software handles device communication and passes data between services, the results database and the user interface.

An example job workflow

  1. 01 · Trigger

    The application interface and APIs support triggering a Jenkins job with the required configuration.

  2. 02 · Device

    Python tools communicate with the board, prepare it for use and automate firmware flashing.

  3. 03 · Execution

    The pipeline coordinates operations across computers and devices and collects job results.

  4. 04 · Data

    Parsers process results, pass them to the database and prepare data for the dashboard.

Areas of team development

Backend and APIs

We develop the layer connecting the web interface with Jenkins and device-management software. APIs support job execution, result retrieval and access to operation details.

Device communication

We build Python tools and a library for sending commands to embedded boards, operating devices remotely and managing their power.

Flashing automation

We integrate firmware flashing with hardware-management tools and Jenkins pipelines. Devices can be prepared for subsequent operations within an automated workflow.

Pipelines and multiple machines

We develop Jenkins pipelines and Python tools that coordinate jobs across computers, connecting environment setup, hardware operations, execution and reporting.

Data processing and dashboards

We retrieve and parse Jenkins results, prepare database writes and develop views for run details, statistics and charts.

Linux and diagnostics

I work with connection configuration, processes and logs on Linux, as well as physical devices. I diagnose issues across code, the operating system and hardware.

Outcomes and adoption

The system is used by Samsung R&D developers working on SoC platforms. Automation reduces manual handling of device preparation, workflow execution and result analysis.

Testing is one use of this environment. The software also covers the backend, hardware communication, data processing and integration between independent components.

A team decision when moving to another project

We compared adapting a similar workflow with building a new implementation and chose to develop it from scratch. This required implementing and verifying the pipeline again.
