Context and purpose

Work on SoC platforms involves operations across multiple computers and physical devices. Board preparation, firmware flashing, job execution and result collection need to work together with applications and CI/CD infrastructure.

The tools we develop reduce manual workflow handling. The software handles device communication and passes data between services, the results database and the user interface.

    The application interface and APIs support triggering a Jenkins job with the required configuration.

  3. 03 · Execution

    The pipeline coordinates operations across computers and devices and collects job results.

  4. 04 · Data

    Parsers process results, pass them to the database and prepare data for the dashboard.

Engineering Automation Platform

System purpose

A shared system for running engineering workflows, processing results and presenting them in a web application. It connects Jenkins, computers and embedded devices with a backend and dashboards.

Team development

I contribute to this platform as part of a seven-person team at Samsung R&D. Together, we develop Python tools, the backend and APIs, result parsers, dashboards and Jenkins integration.

Backend and integrations

The backend connects the web interface, the CI/CD system and device-management software. APIs support triggering Jenkins jobs and retrieving results and information about completed operations.

Data processing

Python tools retrieve and parse Jenkins results and prepare them for database storage and dashboard presentation. The application provides run details, statistics and charts.

Workflow orchestration

Pipelines integrate Python tools with operations across multiple computers and devices. A workflow covers hardware preparation, firmware flashing, task execution and reporting results.

Adoption

The system is used by Samsung R&D developers working on SoC platforms. Automation reduces manual workflow handling, while shared access to results supports troubleshooting.

Engineering decision

When moving to another project, we considered adapting a similar workflow or building a new implementation. The team chose to build the process from scratch. This required implementing and verifying the pipeline again rather than reusing an existing workflow.

Embedded Device Automation

Context and team

This is the device-facing part of the same environment developed by our seven-person team. We build Python software for board communication, remote operations and integration with CI/CD workflows.

Device communication

A communication layer exposes physical-device operations to Python tools. It covers sending commands, controlling boards and managing their power.

Firmware flashing

Tools automate remote firmware flashing and preparation of devices for subsequent operations. The workflow integrates with Jenkins and board-management software.

Multi-machine integration

Software connects computers, devices and Jenkins jobs into one workflow. It coordinates operations and passes their results to other system components.

Linux and diagnostics

I work with connection configuration, processes and logs on Linux, as well as physical devices. I diagnose issues across software, the operating system and hardware.

Validation use

The software is used, among other things, to run automated tests on physical boards and collect results. Communication tools, flashing automation and orchestration make these workflows repeatable.

Outcomes and adoption

The system is used by Samsung R&D developers working on SoC platforms. Automation reduces manual handling of device preparation, workflow execution and result analysis.

Testing is one use of this environment. The software also covers the backend, hardware communication, data processing and integration between independent components.
