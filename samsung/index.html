In a seven-person team, I develop software that automates workflows for developers working on SoC (System on Chip) platforms. My work covers Python tools, Jenkins pipelines and dashboards. I combine coding and data processing with work on physical boards and Linux diagnostics.

From device preparation to result analysis

Working on SoC platforms involves preparing hardware, flashing firmware, executing tasks and reviewing the results. Our system connects these stages into one workflow. Jenkins coordinates execution, Python tools handle operations and data processing, and the backend and web application make results available to developers.

Jenkins pipelines

I build and maintain CI/CD pipelines that coordinate operations on computers and embedded devices. I integrate Python tools with board preparation, firmware flashing, test execution and reporting. These steps form a workflow that can be run again without carrying out each operation manually.

Backend and APIs

The backend connects the web interface, Jenkins and device-management software. APIs allow jobs to be triggered and provide access to results and information about completed operations. As part of the system developed by the team, this layer connects the application entry point with hardware operations and the data later presented in dashboards.

Result processing in Python

I develop tools that retrieve and parse Jenkins results, then prepare them for database storage and presentation in the application. This is the step between running a job and analyzing its outcome: execution data becomes the basis for detailed views, statistics and charts.

Dashboards for developers

I contribute to dashboards that present run details and processed results. Developers use them to investigate issues, accessing data through a shared web application. My work therefore covers both the tools that collect data and its presentation to the engineers working on SoC platforms.

Working with embedded devices

Device communication and firmware flashing

As a team, we develop the communication layer between Python tools and physical boards. It handles commands, power control and remote firmware flashing. Connecting it to Jenkins makes it possible to prepare hardware and run tasks across multiple computers and devices within one workflow. Among other uses, this environment runs automated tests on boards and collects their results.

Diagnosing issues across code, Linux and hardware

I configure connections, inspect processes and logs, and diagnose issues encountered when working with boards. This involves interactions between Python tools, the operating system and the physical device. When investigating a failure, I examine these components in the context of the complete workflow, from starting a job to collecting its results.

How the system supports engineering teams

The system is used by Samsung R&D developers working on SoC platforms. Automation reduces manual device preparation and test execution, while shared access to results supports troubleshooting. My contribution covers the pipelines, Python tools and dashboards that form this workflow together with the other components developed by the team.
